## Findings

1. **Dedicated-server contact delivery is missing.** `BedRuntime`, `BarbRuntime` and `TurretTackServer` register their zombie-contact logic only on `OnZombieUpdate`. Their spatial checks and damage requests are therefore not driven by the dedicated server's normal zombie loop. This covers Bed Spikes, Barbed Panels, Concertina and Tack zombie contact. Visual Tack fields and player contact use different paths; seeing a field does not prove zombie damage. Spike Barrier has an owner strike-report path, so it must not be declared identically broken. Its server actor index and owner changes still need explicit coverage.
2. **Pixel Strike integration is deliberately SP-only.** `DamagePresentation.showDamage` immediately returns on `isClient()`. `OnOMHTTDamage` is raised on the authority, with no client damage-presentation packet. Sending the same event in the production fixture produces one popup in SP and none on MP. Removing the guard alone would not transport the event. Send confirmed actual loss once, with victim identity and captured position; preserve Pixel Strike preferences and suppress duplicate delivery. Capture lethal presentation data before corpse removal.
3. **Conditional modules share a baseline-lifecycle weakness.** `TargetHealth.created` defers maximum-health capture to the first zombie update or hit lookup. Without the server update, an earlier ordinary injury can become the recorded maximum. Production replay: spawn1HP, injury to0.15 before the first turret lookup, then Initial Blow applies its healthy-target bonus and Execute18% fails because the denominator becomes0.15. This is a demonstrated conditional failure mode, not proof of which modules were installed in this latest session. Fix baseline observation along with contact scheduling; never infer a reliable maximum by inventing a constant100HP for all zombies.
4. **Poke has separate timing holes.** `ControlPoke.step` arms a newly observed trap only after1000 simulation milliseconds. An actor can cross during that interval without activation. It also clears `entry.strike` on cycle expiry before processing the strike; a visit after an entire cycle can erase it and immediately start another. Both reproduce against unmodified production Lua; ordinary1150ms strike timing reaches damage. Runtime steps are serviced by the100ms,64-device/2ms Controller scheduler. The captured logs cannot establish the exact visit gap for the owner's observed miss. Repair due-action ordering, avoid a placement/reload blind interval, and never replay an unlimited backlog of expired hits or hit actors that have left.
5. **Default-name localization crosses the wrong boundary.** `ControlWorld.name` calls server `getText`, stores the result through `DefenseNames.ensure`, and `ControlClient.name` returns `state.displayName` verbatim. `UI_OMHTT_ControlPoke/Plate/Button/Lever` exist in EN; adding those keys again cannot fix saved raw names. The production client fixture reproduces the screenshot with a persisted raw default. Replicate kind/head identity and number, localize automatic labels on the viewing client, retain exact custom names, and normalize recognized old automatic labels without renaming user text. Audit graph/map/context/packed-item uses together.
6. **Aim already has smoothing, but catches up too quickly.** The server publishes changed headings at250ms cadence, gated by2-degree buckets. Client `TurretRenderer.animate` turns up to720 degrees/second. Small corrections finish in a frame or two and then wait for the next packet. Replace that presentation rule with shortest-angle interpolation over received samples, bounded recovery after packet gaps, and explicit reset on head/device changes. Do not change authoritative aim, targeting or firing timing. This is a contained visual change; some display latency is the tradeoff. Rotary motion must retain continuous direction across360 degrees.
7. **Observer pack icon is new work.** The existing timed action sends reward presentation only to its opener on completion. Add a small existing Module Pack texture above the opener while the actual opening action is active, restricted to other viewers within8tiles, same floor and normal visibility. Stop/cancel/death/disconnect must clear it; late arrival and moving across the boundary need checks. No rewards or private inventory are broadcast, and no new art is required. Prefer native action lifecycle evidence before introducing extra network messages; no per-frame broadcast.

## Proposed corrective scope and approval

**1A recommended:** fix dedicated-server contact/baseline observation, Poke timing, confirmed damage numbers and automatic labels; include client aim smoothing and the requested eight-tile pack-opening icon. Reuse the existing spatial indices and shared damage authority. Replace undriven server event subscriptions with one bounded contact mechanism; retain SP's native callbacks and avoid scanning every zombie once per trap or trusting client-provided damage. Cover Bed/Barb/Tack, quick pressure/laser crossings, Barrier indexing and conditional health initialization as one lifecycle review. Resolve any unavailable replicated stance data with native evidence rather than assumptions.

**1B:** same correctness repairs and module audit follow-through; defer aiming and the observer icon to a later patch.

Neither option changes damage balance, module stacking, existing permissions or Horde assistance policy. Approval is pending under the project test-feedback agreement. No additional owner test is requested until the corrective build exists.
