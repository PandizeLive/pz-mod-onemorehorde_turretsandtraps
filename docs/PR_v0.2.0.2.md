# v0.2.0.2: Building-menu discovery and diagnostics

The Building menu silently rejected the Spike Barrier because its global visibility dispatcher resolves an exact global name, while the recipe supplied a dotted table path. Register a flat global callback for that dispatcher. Add the missing native UiConfig/Xui style using an existing white arrow marker and refresh the mod recipe's cached translated name when opening the menu. Keep the recipe under Carpentry and add a Turrets & Traps filter over the same recipe; no duplicate entity or crafting transaction is introduced.

Menu diagnostics record registered mod recipes, translated names, native category, callback, search/category state, content enablement and Build Cheat. The owner withdrew the custom requirement-bypass request; vanilla Build Cheat remains the testing route. Approved materials, Carpentry 1, 10 base XP, durability and damage are preserved.

The [owner log review](TEST_v0.2.0.1.md) records the missing UiConfig error and exact native callback-path diagnosis. The native probe reproduces rejection of the old dotted name and checks the replacement under SP-enabled, content-disabled and multiplayer conditions. It also checks one registered recipe, UI style and translated title. These are native dispatcher checks with simulated side flags, not a rendered player UI or multiplayer construction test. Validation and local installation evidence are recorded in [release state](RELEASE.md). The [checkpoint](PHASE_2_CHECKPOINT_1.md#owner-test) contains the complete player test. No Workshop upload or remote push.
