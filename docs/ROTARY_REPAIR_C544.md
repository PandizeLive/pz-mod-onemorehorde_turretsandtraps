# C544: observation-driven rotary replacement

On 2026-11-01 the owner approved C543 **1A**: replace scan-dependent rotary contact sampling with existing validated observations, start wakeup on the first valid detection, keep one motor timeline and server damage authority, and prove the scheduled workflow before packaging. Implemented as **0.2.71.8**. This does not approve unrelated pause-mod, Workshop-publication or sibling-project changes.

## Replacement

The existing server report handler still validates identity, owner, position, age and ordering. Accepted reports now notify the same actor listeners used for native/unowned observations. Traps retain their scoped observation context and receive each report once. Rotary turrets register a local spatial footprint when their head changes; nearby observations advance that motor and check the observed contact interval immediately. The old per-turret tile scan, scan-completion detection, pending-hit lock and competing sweep bookkeeping are removed. The ordinary scheduler remains responsible for idle maintenance and other heads.

The motor uses resolved shared head definitions and module stats, including custom rotary range/cone. Fresh detection starts the existing one-second wake and quarter-second alert delay. Damage compares the target's observed interval with recorded motor travel. Short position/angular slices separate blade passes, including the forward and return passes close to a cone reversal. Duplicate suppression is per arm/pass; distinct passes can use the existing bounded authoritative damage queue while earlier receipts are pending. A first observation, owner change, long gap or unsupported history cannot invent prior contact. Dead/prone, blocked, out-of-range, paused and powered-off cases remain excluded.

Game-time movement and battery spending remain on the active clock. The motor history and transmitted sample use synchronized report timestamps, rather than stamping old travel with a later send time. Existing runtime publication is reused and throttled; start/stop transitions publish promptly. No client damage authority, second protocol, new Sandbox tuning or persistence schema is introduced. Delayed module callbacks retain their paid Siphon pass; stopping closes its energy record. A detailed `rotary-target-observed` event complements existing hit/application diagnostics.
