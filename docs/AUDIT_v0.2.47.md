## Confirmed concerns and recommended fixes

1. **Per-frame tooltip layout work (medium).** `TurretItemTooltip.footer` line 11 calls WrapText and splits the result on every inventory tooltip render. An unchanged tooltip caused 600 wrapping calls across 600 simulated frames. `TurretDescriptions.get` caches the completed description, but still formats its lookup key per call; it does not cache the wrapped layout. Cache the footer lines/layout using description, font and available width, invalidating when those inputs change. Keep native condition/weight details live. This is avoidable allocation/bridge work; no measured in-game stutter is attributed to it.
2. **Reveal viewport overflow (medium, small/split viewports).** `TurretPackReveal.show` line 63 sizes height solely from font height and three rows. At font height 16 it is 382 pixels high; in a 360-pixel player viewport it starts at -11 and ends at 371. Width is constrained, height is not. Use viewport-constrained card sizing or a scrollable interior with fixed reachable buttons, retaining all three reward rows. Existing normal desktop geometry fits; rendered GPU acceptance remains pending.
3. **Packs with no eligible rewards (low, custom-settings edge).** `TurretModulePack.onDeath` checks global rate but not whether all 29 component weights are zero. The audit confirms a corpse pack still drops in that state; `P.open` then correctly refuses to consume it. Container injection also does not check this empty pool. Suppress new pack acquisition when the eligible pool is empty using a cached flag updated with loaded loot settings, rather than scanning all weights on every death. Existing packs must remain intact and become openable after eligibility returns.
4. **Reveal preparation churn (low-priority optimization).** Each opening sorts/rebuilds the 29-entry pool twice (grant and display), creates 29 temporary native item instances for icon/name lookup, and prepares 48 card references. No item factories or wrapping occur during 300 animation frames. Prefer cached/static item display metadata if native access is verified; preserve rarity/localization invalidation. These are bounded occasional costs, so a permanent queue/tick system is not justified by this audit.

No balancing choice is required for the three recommended corrections. Keep the approved 15%, three rewards, duplicates and supplied weights. The 15% default means an expected 150 packs / 450 module or expansion rewards per 1,000 bodies; this is intentional generous progression, not a probability bug. LootLab still excludes packs from map totals and says so explicitly.

## What was checked

- Pack acquisition uses OnZombieDead; inventory option uses OnFillInventoryObjectContextMenu. The pack feature registers no new OnTick or world/corpse scanner. Opening update work exists only during its timed action; reveal render work exists only while its window is open.
- Each death performs a small constant-size guard/RNG path and inserts at most one item. Exhausting RNG values 0-9999 over 10,000 fresh mock deaths, with a second callback for every death, yields exactly 1,500 packs and 10,000 rolls. This checks the boundary/once-only logic; it is not an observed random-world drop frequency.
- Failed grants at reward 2 and reward 3 roll back inserted rewards and keep the original pack. A failed pack removal rolls back all rewards; retry succeeds. Existing native 0.2.47 tests additionally establish real-item exchange and fresh-process reward-table persistence. No duplication/loss defect was found in those tested paths.
- Reveal layout/card preparation is bounded: 29 prepared display items, three reels of 16 references, at most four visible cards per row at the normal 540-pixel width. Rendering did not create new items or wrap text in 300 frames. Leaving the finished window open continues normal rendering, not new reward processing.
- Battery duration remains arithmetic rather than a loop per remaining shot; it is calculated on tooltip demand and cached against relevant charge/loadout/timing inputs. Manage's existing refresh is limited to once per 200 ms. The hour patch changes only formatting; boundary tests still pass.
- All 29 supplied per-item values exactly match the game defaults on the unchanged raw-weight scale. Existing saved settings intentionally remain unchanged; current pack selection and rarity use the loaded values. Package source/Contents match the installed immutable tag.
- Native vanilla transferIfNeeded/haveToBeTransfered still queues transfer from a bag or external container before opening; the action requires the exact pack in the player's main inventory. No new always-on transfer polling was introduced.
